# 单位资产导入与 Source 维护

通过现有 MCP 组合资产导入、Source 配置和更新导出操作。资产导入与 Mass 运行时渲染是两个步骤。

## 导入流程

1. 解包后，将模型连同骨骼、动画、贴图一起导入 UE，保留原材质、UV、装备和动作。不把解包当作导入完成。
2. 创建或更新 Unit Source Actor，在源蓝图配置整单位模型、动画映射、武器和开火点。不同武器负载保留独立 Source／单位版本，不依赖游戏支持动态换枪。
3. 调用 Source 的 Update／更新导出入口，由既有转换流程生成或更新 Mass 单位及所需网格、LOD、VAT、材质和渲染配置。烘焙、尺寸与坐标转换复用既有流程；坐标只转换一次，不在外侧另加旋转、缩放或烘焙流程。
4. 抽样对照原资产和生成结果，查看贴图、材质、朝向、尺寸、动画及开火点，并截图验证实际显示。分别报告资产导入、单位转换和实际显示结果。

## 执行边界

Source 配置完成后调用 Update，由既有流程完成转换、烘焙、生成资产及其关联。流程到这里即完成单位资产更新；截图是验收，不是另一套制作流程。

- 不增加“接通实际渲染引用”“同步旧副本”“更新血条渲染副本”等人工步骤，不假设存在需要额外维护的副本。
- 不绕开 Source，手动重绑生成的 Niagara、渲染器或材质；不另写转换器、烘焙器、同步脚本或运行时补偿逻辑。
- 导入已有成品不授权重做动画、调整动作混合、切换 VAT 模式或材质父级。没有用户要求，不改变这些内容。
- 调用失败时，依据实际返回，只处理当前入口缺少的参数或错误调用。不猜测 GPU、缓存或旧副本问题，不通过反复切换配置试错。涉及公共转换能力的修改须遵守项目授权范围。
- 新兵种接入兵营生产、升级替换属于用户另行要求的业务配置，复用已有入口；不得把它与单位内部渲染关联混为一谈。
- 按资产包抽样验收本次指定结果，通过即停止。不重复导入已成功资产，不以反复录制预览代替交付。

本技能规定维护职责，不虚构 MCP 命令或成功记录。已有成功调用直接复用；缺少具体命令签名时，只查询该操作所需的当前接口，不把概念流程冒充已验证的接口配方。

## 后续维护

换动画、换武器或调整挂点，修改同一个 Source，再更新导出。只改动画时，保留模型、材质、单位尺寸、血条、数值和既有攻击绑定，不重新套用模板覆盖其他配置，不直接拼改生成资产。

Winyunq 项目的官方 Source 类型为 `/Script/MassBattleEditor.MassBattleUnitSourceActor`，更新入口为 `Update()`；不要与 `/Script/MassBattleEditorMCP.MassBattleUnitSource` 混淆。具体 MCP 命令和参数以当前接口为准；一个工具集未列出导入操作，不代表整个 MCP 不支持导入。

项目命名、尺寸、坐标和数值遵循项目既有规范。本流程不授权修改框架源码或新增运行时换枪机制。
